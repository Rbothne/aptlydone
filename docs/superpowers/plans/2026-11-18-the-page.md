# The Page Implementation Plan (plan 3 of 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the status page with the real one: buildings first, each showing its five best units for the current filters, with tags, true monthly cost, floor-plan drawings and stars.

**Architecture:** A static page with no build step. `site/js/logic.js` holds every decision as pure functions (filtering, ordering, picking the best units, wording), tested with Node's built-in test runner. `site/js/store.js` keeps stars and filters in the browser. `site/js/app.js` loads the data files and renders. Styling follows the owner's wishlist site (warm paper background, dark green accent, pill buttons, light and dark).

**Tech Stack:** Plain HTML, CSS and JavaScript modules. Tests: `node --test tests/js/`.

**Spec:** `docs/superpowers/specs/2026-11-18-apartment-tracker-design.md`, sections 10 and 15.

## Global Constraints

- No libraries, no build step. Everything the page shows comes from `site/data/index.json` and `site/data/units-<county>.json`.
- Browser storage is wrapped in try/catch; the page works without it.
- Nothing is presented as known when it is not: unknown laundry says "laundry not stated"; a building with no prices says so; a starred unit that disappears says "no longer listed".
- Income-restricted units and senior housing are hidden unless switched on. Rooms under 300 sqft are labelled "room".
- Works at phone width without sideways scrolling.

## Review Focus

1. A unit with no true monthly cost (`true` null): expected to list with its rent and sort last on cost sorts, not vanish or sort first.
2. A filter that leaves a building with no matching units: expected to hide the building, and the count line to say how many buildings and units match.
3. Stars for units that are no longer in the data: expected to stay in Followed with last known details and "no longer listed".
4. Storage unavailable (private window): expected to render and filter normally, just without remembering.
5. A building with one unit and a building with two hundred: expected both to render sensibly ("show all 200" expands in place).

### Task 1: Decisions as pure functions

**Files:** Create `site/js/logic.js`, `tests/js/logic.test.mjs`.

**Produces (all exported):**
- `DEFAULT_FILTERS`: `{q: "", beds: [], minSqft: null, maxCost: null, moveBy: null, floorMin: null, floorMax: null, ground: false, laundry: false, parking: false, pets: false, tagged: false, county: "", showRestricted: false, sort: "picks"}`.
- `unitMatches(unit, building, filters) -> boolean`. `beds` holds 0, 1, 2 or 3 (3 means three or more); `maxCost` compares `unit.true ?? unit.rent`; `moveBy` keeps units available on or before that date; `ground` keeps floors 0 and 1; `laundry` needs `building.laundry === "in_unit"`; `parking` needs `building.parking_from != null`; `pets` needs `building.pets === true`; `tagged` needs a tag; unless `showRestricted`, restricted units and senior buildings are out; `q` matches building name, neighborhood, manager, city or ZIP, case-insensitively.
- `compareUnits(sort) -> (a, b) => number` for `picks` (tag order absolute, building, local, none; then `own.pct` ascending with missing last; then cost per sqft), `cost`, `ppsf`, `own`, `local`, `newest` (`first` descending), `size` (sqft descending). Missing values sort last in every sort.
- `groupBuildings(index, unitsByBuilding, filters, bestCount = 5) -> [{building, units, best}]`: buildings that have at least one matching unit, each with all matching units sorted and the first `bestCount` as `best`, ordered by their best unit under the same sort.
- `tagLabel(tag)`, `tagReason(unit) -> string` ("15% under 6 similar units in this building · 21% under 14 units in 4 buildings within 1 mile").
- `money(n)`, `perSqft(unit)`, `ago(isoTime, now) -> "2 hours ago"`, `shortDate("2026-11-29") -> "Nov 29"`.
- `sparkline(history, width, height) -> string | null`: SVG path data for the rent series; `null` with fewer than two points.

### Task 2: Browser storage

**Files:** Create `site/js/store.js`, `tests/js/store.test.mjs`.

**Produces:** `createStore(storage) -> {getFilters(), setFilters(f), stars(), isStarred(id), toggleStar(unit, building), refreshStars(unitsById)}`. A star keeps a copy of the unit and its building's name and address; `refreshStars` updates copies for units still listed and marks the rest `listed: false`. Every storage call is guarded; with a storage that throws, the store keeps working in memory.

- [ ] Tests first with a fake storage and a throwing storage. Fail, implement, pass, commit.

### Task 3: The page

**Files:** Rewrite `site/index.html`; create `site/app.css`, `site/js/app.js`.

- Sticky header: title, tabs **Buildings** and **Followed** with counts, the filter bar (search; bed chips; min sqft; max monthly; move in by; floor from/to and "Ground floor"; switches for in-unit laundry, parking, pets, tagged only, show income-restricted and senior; county; sort), and a count line ("Updated 2 hours ago · 128 buildings · 913 units match").
- Building card: name (link), rating, neighborhood, manager, rank ("pricier than 60% of 12 nearby buildings"), offer banner, facts line (laundry, parking from, pets, one-time fees), and its best five unit rows with "Show all N".
- Unit row: tag chip, unit, beds/baths, sqft, floor, true monthly cost with per-sqft and the "if the offer applies" figure, comparison percents, available date, lease term, sparkline, star. Clicking a row opens details: floor-plan drawing, rent and fee breakdown, tag reason, price history list, link to the building's site.
- Buildings render 30 at a time with "Show more". Buildings with no published prices are listed in a closing section.
- Followed: starred units grouped by building, including ones no longer listed.
